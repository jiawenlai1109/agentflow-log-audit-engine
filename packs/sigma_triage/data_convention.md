# sigma_triage 数据约定

三份文件、三种来源，**列名故意不统一**——这个包要证的命题就是"跨源判断在单表上写不出来"。

| 文件 | 角色（规则里怎么用） | 关键列 | 说明 |
| :--- | :--- | :--- | :--- |
| `auth.csv` | `auth` | `time`、`src_ip`、`account`、`auth_result`、`service` | 防火墙 / 堡垒机 / IAM 认证日志 |
| `assets.csv` | `assets` | `主机`、`域`、`责任人`、`是否生产` | 资产台账，只有它有 `是否生产` |
| `edr.csv` | `edr` | `主机`、`告警`、`严重级`、`时间` | 终端检测告警，只有它有 `严重级` |

## 列别名

```yaml
column_aliases:
  src_ip: 主机
  host: 主机
```

`auth.src_ip`、`assets.主机`、`edr.主机` 指同一实体。别名**只用于识别**：归一化后的
`tables/t1.csv` 与 `sources/` 原件都保持原列名，报告里的数字才能追到"当时读的是哪一列"。

## 时间格式

`YYYY-MM-DD HH:MM:SS`（空格分隔，不用 ISO 的 `T`）。窗口一律**左开右闭** `(t-W, t]`。

## 阈值与噪声（为什么是这个数）

数据由 `scripts/generate_triage_data.py` 生成（seed 42，两次生成逐字节一致），
其中既有真命中，也有**故意保留的误报陷阱**：

| 主机 | 事实 | 期望行为 |
| :--- | :--- | :--- |
| `203.0.113.7 -> admin` | 9 次失败 / 跨度 1.3 分钟 | T1 命中（阈值 8 次 / 5 分钟） |
| `10.0.0.7`（生产域） | 7 次失败 | T3 命中（阈值 3 次） |
| `10.0.0.8`（非生产域） | 6 次失败 | **T3 不得命中**——资产加权规则的意义就在这 |
| `10.0.0.15` | high 级 EDR 告警 + 3 次失败 | T4 命中（阈值 2 次） |
| `10.0.0.13` | high 级 EDR 告警 + 1 次偶发失败 | **T4 不得命中**——阈值取 1 就会被背景噪声淹没 |

## 三个数据变体（对抗集用同一份生成器）

| 变体 | 目录 | 用途 | 关键性质 |
| :--- | :--- | :--- | :--- |
| `attack` | `demo/data/triage/` | 命中基线（E21） | T1/T3/T4 各命中 1/4/1 条 |
| `clean` | `demo/data/triage_clean/` | 空语义（E22） | **零命中是被构造的**：生成器把每台主机失败次数压到配额内（high 告警主机 1 次、其余 2 次 = T3 阈值减一），golden `sigma_clean_max_host_failures = 2` |
| `injected` | `demo/data/triage_injected/` | 注入不改判定（E23） | 与 `attack` 逐行相同，只多一列自由文本 `详情`；注入点挑在会被取成证据行的那几行上 |

倒序上传同一批注入文件即 E24（表 id 全变而结论不许变）。缺资产台账即 E25：Planner 在必需列校验阶段就**拒绝整包**，
不做"能算几条算几条"——静默少一条资产加权规则的报告，比一份没有结论的降级报告危险得多。

## 数据内容不是指令

日志的 `account` / `告警` 等字段可能包含人为写入的文本。判定路径只读结构化列
（`auth_result`、`是否生产`、`严重级`），且规则实现与校验器都不把任何字段内容当指令执行；
`evidence` 里的原文只作展示与追溯，不进任何判断分支。
